# Traders Care — лендинг: инструкция для интеграции

Это самостоятельный проект главной страницы traderscare.io (Next.js 15, React 19, Tailwind 3). Его нужно перенести в сайт-платформу Traders Care (traderscare.io — публичные страницы и рабочее пространство в одной кодовой базе). Ниже — что где лежит и что учесть при переносе. Перед интеграцией прочитай этот файл целиком.

## Как устроен проект

- Страница: `src/app/[locale]/page.tsx` — собирает блоки по порядку.
- Блоки: `src/components/sections/*`. Шапка, подвал, переключатели темы и языка: `src/components/site/*`.
- Тексты: `src/i18n/dictionaries/{ru,en,uk}.ts`. Тип словаря выводится из `ru.ts`, остальные языки обязаны ему соответствовать — TypeScript проверяет это сам.
- Цвета: CSS-переменные `--lp-*` в `src/styles/tokens.css`, в Tailwind — классы `lp-*` (`bg-lp-ground`, `text-lp-text`, `text-lp-loss`…). Префикс `lp-` выбран, чтобы не пересекаться с токенами платформы (дизайн-система CARE).
- Тема: атрибут `data-theme="dark" | "light"` на `<html>`, ключ `localStorage` — `theme`. Это те же соглашения, что на платформе. Светлые варианты в разметке пишутся как `[[data-theme=light]_&]:…`.
- Картинки и кадры первого экрана: `public/media/` (~11 МБ, из них ~10 МБ — кадры `public/media/hero/lid*`).
- Шрифты: `next/font` в `src/lib/fonts.ts` (Wix Madefor Display/Text, JetBrains Mono, лицензия SIL OFL). Подключаются CSS-переменными `--lp-font-display`, `--lp-font-text`, `--lp-font-mono` на `<html>`.
- Зависимости сверх Next/React: `motion`, `lucide-react`, `lucide` и `morphicons` (morphicons работает с иконками из пакета `lucide`, поэтому нужны оба).
- Проверки: `npm run lint` (ESLint, `eslint.config.mjs`), `npm run typecheck`, `npm run build`. Все проходят без ошибок и предупреждений.
- `package.json` содержит `overrides.postcss` — поднимает версию postcss внутри Next до исправленной (уязвимость в 8.4.x). При переносе добавь то же в `package.json` платформы.

## Что учесть при переносе

Эти места настроены под отдельный проект. При переносе их нужно согласовать с платформой, а не копировать как есть.

1. **Tailwind-конфиг** (`tailwind.config.ts`) переопределяет общие вещи:
   - `screens` — свои брейкпоинты (`sm: 480px` вместо стандартных 640px и т. д.). Вёрстка лендинга рассчитана на них.
   - `fontFamily.sans / display / mono` — указывают на шрифты лендинга.
   - `spacing.section`, `spacing.header`, `borderRadius.control/screen/media`, `fontSize.lp-*`, `maxWidth.container`.
   Не сливай это в конфиг платформы вслепую: изменение `screens` и `fontFamily.sans` поменяет вёрстку всего сайта, включая рабочее пространство. Варианты: отдельный Tailwind-конфиг для маршрута лендинга, либо перенести только `colors.lp`, `fontSize.lp-*` и прочие ключи с уникальными именами, а брейкпоинты в классах лендинга заменить на эквиваленты платформы.

2. **Глобальные стили** (`src/app/globals.css`):
   - `@layer base` задаёт фон, шрифт и размер текста для `body`, стили `h1–h3`, `:focus-visible`, `::selection`.
   - `tokens.css` выставляет `color-scheme` на `:root`.
   - Правила `::view-transition-*` и `.theme-switching` — анимация смены темы («полоса света») и языка.
   Всё это затронет остальные страницы платформы, если подключить глобально. Ограничь базовые стили контейнером лендинга или подключай `globals.css` только в layout маршрута лендинга. Остальные классы в `globals.css` (`.receipt*`, `.thermal`, `.hero-mark`, `.phone-swap`, `.screen-in`, keyframes) уникальны и нужны блокам.

3. **Корневой layout** (`src/app/layout.tsx`) содержит `<html>`, `<body>`, шрифты и `ThemeScript`. На платформе это уже есть — не дублируй. Нужно только добавить классы шрифтов (`fontVariables`) и убедиться, что `data-theme` ставится до первой отрисовки (у платформы свой скрипт с тем же ключом `theme` — используй его).

4. **Маршрутизация языков** (`src/middleware.ts`): английский без префикса, `/ru` и `/uk` с префиксом. У платформы такая же схема и свой middleware — используй его, этот файл не переноси. Смена языка без перезагрузки — `src/components/site/locale-link.tsx` и `src/lib/locale-transition.ts`.

5. **Шапка и подвал** (`src/components/site/`) — свои, для лендинга. Реши с командой, заменяют ли они общую публичную шапку платформы или лендинг использует её. На платформе кнопка «Войти» для вошедших меняется на «Workspace» — в шапке лендинга этого нет.

6. **Ссылки на другие страницы платформы** собраны через константу `APP_URL` (`src/i18n/config.ts`, сейчас `https://traderscare.io`): `/register`, `/register?plan=free|solo|trader|pro`, `/login`, `/prop-firms`, `/prop-firms/match`, `/tools/*`, `/legal/*`. После переноса их стоит сделать относительными и сверить с реальными маршрутами.

## Временные данные

Комментарий `[ДАННЫЕ]` в коде отмечает места, где данные нужно подтвердить или заменить:
- число трейдеров «12 400+» в полосе доверия (`trust` в словарях);
- фирмы на картах каталога и число их программ — примеры (`prop-firms.tsx`);
- адреса калькуляторов, документов, соцсетей, почты и Telegram поддержки (`prop-firms.tsx`, `faq.tsx`, `footer.tsx`, словари);
- картинка для превью ссылки в соцсетях (`og:image`) не задана (`src/app/[locale]/layout.tsx`);
- цены, лимиты и уровни ИИ в тарифах — взяты из продуктовой документации, проверь по актуальным значениям из админки.

Демонстрационные цифры в интерфейсах (−$2 340, 14 сделок и т. д.) согласованы между блоками и подписаны на странице «Пример данных». Если менять одну, проверь остальные: чек (`how-it-works.tsx`), экран ноутбука (`laptop-screen.tsx` и `hero.visual.screen` в словарях), ответ ассистента (`ai` в словарях).

## Важные детали реализации

- **Первый экран** (`hero-laptop.tsx`): видео разложено на 144 кадра, они рисуются на `<canvas>` в зависимости от прокрутки. Скорость ограничена (`MAX_FPS`), кадры грузятся в фоне после загрузки страницы, распаковываются только соседние. Для телефона — отдельные лёгкие кадры (`lid-m`, `lid-light-m`), для светлой темы — свои (`lid-light*`). Не заменяй на `<video>`: прокрутка по видео в Safari работает рывками.
- **Экраны на фото** (ноутбук, телефон, iPad, планшет на столе) свёрстаны кодом и наложены на изображение. Ноутбук, телефон и планшет на столе сняты под углом — для них матрица перспективы из `src/lib/homography.ts`; iPad снят прямо, там простое масштабирование. Координаты углов экрана записаны константами в начале каждого компонента. Если заменить картинку — координаты нужно перемерить.
- **Анимации** проигрываются один раз при появлении блока (`src/components/ui/reveal.tsx`, хук `useOnce` в `firm-tools.tsx`) и уважают `prefers-reduced-motion`.
- **Наведение на телефоне**: всё, что на десктопе реагирует на наведение, на сенсорных экранах работает по нажатию. Сохраняй это при правках.
- **Доступность**: проверено axe-core — 0 нарушений в обеих темах и на телефоне. Декоративные сцены помечены `aria-hidden`, их смысл передан текстом для скринридеров.

## Проверка после интеграции

- `npm run lint`, `npm run typecheck` и сборка без ошибок.
- `/`, `/ru`, `/uk` открываются; язык и тема переключаются.
- На ширине 360–390 px нет горизонтальной прокрутки.
- Первый экран: крышка открывается плавно, в светлой теме — серебристый ноутбук.
- Остальные страницы платформы (каталог фирм, инструменты, рабочее пространство) выглядят как до интеграции (особенно после изменений в Tailwind-конфиге и глобальных стилях).
